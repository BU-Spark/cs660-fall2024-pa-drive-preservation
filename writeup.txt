								Design Decisions


B Tree->The BTreeFile class handles data storage in a B+ tree, starting with a specified key index to keep entries ordered. 
insertTuple finds the right leaf for each new entry and manages splits that may go up the tree, creating a new root if necessary. 
getTuple retrieves entries safely, and `next` allows sequential traversal by advancing the iterator. 
begin and end provide easy access to the start and end of the tree, supporting ordered scans. 
A placeholder deleteTuple function allows for future deletion features. Together, these decisions keep data balanced and accessible in the B+ tree.

Leaf Page->The LeafPage class is designed to efficiently handle tuples within a B+ tree leaf node. 
It starts by calculating how many tuples the page can hold, allocating space for both the header and data. 
The insertTuple function maintains a sorted order, checking for duplicates and shifting existing tuples if necessary. 
When the page fills up, the `split` function divides it by moving half the tuples to a new page and returns a key for indexing purposes. 
The getTuple function safely retrieves a tuple based on its position, with checks to prevent out-of-bounds access.
Altogether, these choices support effective storage, orderly data management, and balanced splitting to keep the B+ tree operating smoothly.


Index Page->The IndexPage class is designed to manage keys and child pointers efficiently within a B+ tree's internal node. 
During setup, it calculates available space, sets up memory for keys and child pointers, and initializes the header. 
The insert function keeps keys sorted by finding the right position, shifting entries as necessary, and returns whether the page is full. 
When a split is needed, the split function divides the page, moving half the entries to a new page and returns the middle key to help update the parent node.
This design supports efficient inserts, maintains order, and ensures balanced splits to keep the tree performing well.
